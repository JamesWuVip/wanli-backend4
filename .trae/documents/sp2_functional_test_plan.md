# SP2功能测试计划文档

## 1. 文档概述

### 1.1 文档目的

本文档详细描述了Wanli Academy项目SP2阶段的功能测试计划，包括极简用户认证和教育业务功能（教育机构管理、课程管理、学员管理）的测试策略、测试用例和验收标准。

### 1.2 适用范围

* 极简用户认证功能测试

* 教育机构管理功能测试

* 课程管理功能测试

* 学员管理功能测试

* 课程学员关联功能测试

* API接口测试

* 集成测试

### 1.3 版本信息

* 测试计划版本：v1.0.0

* 对应SP2版本：v2.0.0

* 创建日期：2025-01-17

* 测试周期：2025-01-20 \~ 2025-01-24

### 1.4 测试环境

* **开发环境**: localhost:8080

* **测试环境**: staging.wanli.edu

* **数据库**: PostgreSQL 15+

* **测试工具**: Postman, JUnit 5, Spring Boot Test

## 2. 测试策略

### 2.1 测试层次

```mermaid
pyramid
    title 测试金字塔
    
    "E2E测试" : 10
    "集成测试" : 30
    "单元测试" : 60
```

* **单元测试 (60%)**: 测试单个方法和类的功能

* **集成测试 (30%)**: 测试模块间的交互和API接口

* **端到端测试 (10%)**: 测试完整的业务流程

### 2.2 测试类型

* **功能测试**: 验证功能需求是否正确实现

* **接口测试**: 验证API接口的正确性和稳定性

* **数据库测试**: 验证数据持久化和查询的正确性

* **安全测试**: 验证认证授权机制的安全性

* **性能测试**: 验证系统在正常负载下的性能表现

### 2.3 测试原则

* **测试驱动**: 先写测试用例，再实现功能

* **自动化优先**: 优先编写自动化测试用例

* **持续集成**: 每次代码提交都运行测试

* **覆盖率要求**: 单元测试覆盖率 ≥ 80%，集成测试覆盖率 ≥ 70%

## 3. 测试范围

### 3.1 功能模块测试范围

| 功能模块  | 测试范围             | 优先级 | 预计工时 |
| ----- | ---------------- | --- | ---- |
| 用户认证  | 注册、登录、JWT验证、权限控制 | 高   | 8小时  |
| 机构管理  | CRUD操作、状态管理、数据验证 | 高   | 12小时 |
| 课程管理  | CRUD操作、状态流转、业务规则 | 高   | 16小时 |

| API接口 | 请求响应、错误处理、数据格式   | 高   | 20小时 |
| 数据库   | 数据持久化、约束验证、查询性能  | 中   | 8小时  |
| 安全性   | 认证授权、数据安全、输入验证   | 中   | 8小时  |

* 密码重置功能（推迟到SP3）

* 用户状态管理（推迟到SP3）

* 操作日志功能（推迟到SP3）

## 15. 风险评估

### 15.1 技术风险

* **数据库性能**: 大量数据时查询性能可能下降

* **并发处理**: 高并发时可能出现数据一致性问题

* **内存使用**: 复杂查询可能导致内存占用过高

### 15.2 进度风险

* **测试时间紧张**: 5天测试时间可能不够充分

* **环境问题**: 测试环境不稳定可能影响测试进度

* **缺陷修复**: 发现的缺陷修复可能延迟交付

### 15.3 风险应对措施

* 优先执行高优先级测试用例

* 准备备用测试环境

* 建立快速缺陷修复流程

* 制定应急发布计划
